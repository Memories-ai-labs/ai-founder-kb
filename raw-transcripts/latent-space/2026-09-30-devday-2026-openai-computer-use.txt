## Episode Overview

This DevDay coverage episode explores OpenAI's major announcements including Dots (personal assistant product), GPT-6.1 Sol, Agents API with Computer Use integration, and the Decisions API — developed in just one week inspired by Jev.

## Key Segments & Transcript Content

### Introduction & DevDay Announcements
Ari highlights several announcements: Dots with personal cloud Linux computers, GPT-6.1 Sol (1/5 cost of Astra, 1/7 cost for Computer Use), Agents API integration with Computer Use, app shots, and native Mac Computer Use capabilities.

### Computer Use Evolution

**Ari on progress:** "Computer Use is, like, 180 degrees different than it was" (from months prior). Key improvements include better debugging/recovery from failures, agents writing JavaScript code, multimodal interfaces using screenshots, accessibility data, Playwright, and DOM access.

**Speed achievements:** Computer Use now completes certain tasks faster than average humans. Ari's example: meal prep ordering took him 2 hours manually but 15 minutes via Computer Use.

### How Computer Use Works

App shots provide models with rich context beyond screenshots — including raw accessibility representations, link destinations, and calendar details. This accessibility technology (designed for screen readers) proves equally valuable for LLMs.

### Computer Use Safety & Developer Guidance

Key recommendations include obtaining user consent before consequential actions like payments, limiting agent access to necessary websites/applications only, and leveraging OpenAI's trained Computer Use harness for speed/cost advantages.

### Superhuman Computer Use Vision

Ari envisions Computer Use achieving superhuman performance — faster than expert users. Current bottlenecks include model capability, inference speed, harness efficiency, and operational latency (e.g., website load times).

## API Innovations

### Async Tool Calling & WebSockets

Nikunj explains that models no longer pause during tool execution. Async tool calling and WebSockets enable continuous reasoning while tools run, then incorporate results mid-turn — a capability requiring model training.

### UltraFast Inference

OpenAI's inference team achieved dramatic speed improvements. Luna model cost dropped 80% through efficiency gains; focus shifted toward extreme latency reduction.

### Decisions API Story

The Decisions API emerged from internal inspiration by Jev (competitor product). Within one week, OpenAI's team prototyped and developed this fast classification system. It's currently a Luna wrapper optimized for speed — not a separately trained model.

**Key differentiators from Jev:**
- Uses Luna weights (no new training)
- Leverages structured outputs
- Parallel inference across multiple questions
- Vision capability included
- Built-in confidence/calibration still developing

## Caching & Performance Improvements

**Prompt caching advances:**
- 30-minute cache hit guarantees
- 12-hour caching window (preview) for persistent agents
- Cache pre-warming for anticipated prompt usage
- Server-side automatic compaction or manual /compact control

**Cost reduction:** 25% cheaper with new model pricing plus cache optimization.

## Developers Should Build

**Decisions API uses:** Support ticket classification, GPT Live tool calling, LLM-as-judge evaluation

**Agents API use cases:**
- Codex security features
- Meeting notes integration with calendar/documents
- Edit spaces and collaborative workflows

## Higher-Level Platform Primitives

Nikunj references Stripe's evolution: building higher-level abstractions atop core primitives. OpenAI grapples with similar questions — balancing flexibility (raw API + example harness) versus built-in abstractions (memory, storage concepts).

**Vision:** OpenAI is essentially building an "AI cloud" — the AI-native equivalent of AWS's EC2 and S3 infrastructure layers.
