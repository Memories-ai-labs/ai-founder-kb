# PRs NOT Welcome: How Top AI Open Source Projects Are Managing Thousands of Contributors
# URL: https://www.latent.space/p/pr-not-welcome
# Date: 2026-09-01
# Source: Latent Space (latent.space)

Author: Richard MacManus

## Summary

Major AI-native open source projects are fundamentally changing how they handle community contributions. Instead of accepting pull requests from external contributors, projects like Vercel's AI SDK, Astro, Flue, and tldraw are deploying their own AI agents to manage code improvements and bug fixes while limiting or closing external PRs entirely.

## Key Developments

**Vercel's Software Factory Approach**

Vercel implemented an agent-based system for its AI SDK project to manage over 1,000 open issues and 800 pull requests. The system deploys specialized agents for bug reproduction, fix implementation, and code review. Within four weeks, the factory was "authoring between 25 and 35% of PRs we merge and closing 70-80% of issues."

**Astro's Success with Auto-Triage**

Astro web framework creator Fred Schott explained that "issues came in faster than we could handle them," but agents now handle triage and reproduction, with users verifying fixes before human review. This represents a significant shift in open source management.

**Flue and tldraw's PR Rejection Policies**

Both projects automatically close external pull requests, converting them into issues or discussions instead. According to tldraw founder Steve Ruiz, this approach recognizes that "it's better to limit community contribution to the places it still matters: reporting, discussion, perspective, and care."

## Underlying Rationale

Maintainers trust their own optimized agent configurations more than community-submitted code. Vercel engineer Lars Grammel noted that having "your own agents and setup" can "cut down your time to review" compared to evaluating external contributions.

## Community Concerns

While these approaches solve immediate scalability problems, questions remain about how community members can advance into maintainer roles if code contributions are no longer accepted. The emphasis has shifted toward discussion and issue reporting as pathways for community involvement.
