## Episode Summary

Supabase co-founders Paul Copplestone and Ant Wilson discuss why Supabase has become a favored backend for AI agent builders, along with major new infrastructure announcements.

## Key Topics

**Why agents love Supabase:**
- Supabase's Postgres-native architecture maps well to agent memory and state management needs
- Vector search (pgvector), structured data, and real-time subscriptions in one platform
- MCP (Model Context Protocol) support makes Supabase databases agent-accessible out of the box

**New Infrastructure Announcements (private alpha):**

1. **Supabase Compute** — runs workloads alongside the database
   - Enables compute-close-to-data patterns favored by agent architectures
   - Private alpha stage

2. **Multigres** — highly available Postgres
   - Supabase's approach to HA Postgres
   - Addresses reliability needs for production agent deployments
   - Private alpha stage

3. **Turso Acquisition** — tied to Supabase's scale-out plans
   - Turso (libSQL/embedded SQLite) acquisition extends Supabase's reach to edge/embedded use cases
   - Strategic move for AI agent deployments at edge

**Supabase Select:**
- New event/conference format discussed in episode
- Community and ecosystem focus

## Context for AI Founders

Supabase has emerged as a top backend choice for AI startups and agent builders because:
- Open source (self-hostable for data sovereignty)
- Postgres familiarity reduces adoption friction
- Built-in vector search removes need for separate vector DB
- Fast iteration speed matches AI startup development velocity
- MCP native support accelerates AI agent integration
