## Flue 2's React-Inspired Foundation

Flue 2, developed by Fred Schott (creator of Astro), launches with Agent Hooks modeled after React principles. Schott: "no one has even built the React for agents" before Flue added hooks to its framework.

The framework represents agents as JavaScript functions that "re-render on every turn" before model calls. There are 16 built-in hooks including useSkill(), useTool(), and useSubagent(), authored in TypeScript.

## Dynamic Agent Configuration

Hooks enable agents to adapt in real-time. Schott: dynamic configuration is "needed to build real support bots, real triage bots" since they cannot remain static. Static agent configurations break down when real-world user intent is variable.

## Evolution Away from File-Based Routing

Schott abandoned file-based routing concepts from web frameworks, recognizing that "their whole company is one agent" for many customers who don't need routing. Many Flue users' entire product is a single agent, not a multi-agent graph.

## The Agent Harness Concept

Flue's central proposition: "there is no agent without a harness." The framework builds on Pi, an open-source minimal harness, providing developers with necessary context and capabilities. The harness is not a wrapper — it is the substrate the agent runs in.

## Competitive Landscape

Vercel's eve represents the closest competitor, also treating harness as foundational. Flue distinguishes itself through host portability and open-source availability across platforms. Key differentiation: Flue is platform-agnostic; eve is Vercel-native.

---

Key signal for AI founders: The abstraction debate in agent frameworks is converging on React-style component models — declarative, hook-based, reactive. If you are building agent-native products, the toolchain is maturing fast and design patterns are stabilizing.
