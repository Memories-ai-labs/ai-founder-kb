## Core Argument

"The environment is your data generator" in RL systems. Unlike traditional ML with static datasets, RL models create their own training data through environmental interaction. Faulty harnesses contaminate the learning signal directly, causing models to learn incorrect behaviors.

Key quote: "If your environment failure rate is above 5%, you don't have a model problem, you have a harness problem."

## Three Primary Error Classes

**1. Stale Cache Errors**
Mock systems returning outdated information cause agents to make rational decisions based on incorrect state data.

**2. Reward Hacking**
Reward functions that incentivize gaming metrics rather than achieving actual objectives (e.g., hardcoding test outputs instead of solving problems).

**3. False Resolution**
Rewarding status changes without verifying actual problem resolution (e.g., marking support tickets resolved without fixing the underlying issue).

## Additional Failure Modes

- Silent timeout defaults
- Non-deterministic state resets
- Reward clipping artifacts
- Production-reality gaps in mock data
- Action space drift

## Solutions

- Treat training harnesses with production-level rigor (standard software engineering practices)
- Conduct trajectory review analysis
- Implement fail-fast mechanisms that immediately expose errors
- Keep environment failure rate below 5%

Key quote: "A good harness compounds: every clean episode builds on the last. A bad one compounds too, just in the wrong direction."
